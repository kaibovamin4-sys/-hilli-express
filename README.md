# AUA — гиперлокальный мониторинг воздуха в Алматы

Сайт отвечает родителю за 5 секунд: **«Можно ли сейчас гулять с ребёнком в моём районе?»** — и честно показывает, откуда взялась оценка. Данные — собственная сеть станций на ESP8266 с газовыми сенсорами MQ2/MQ4/MQ8 + открытые модели Open-Meteo (PM2.5, погода, пыльца).

```
aua-almaty/
├── src/                  # фронтенд: React 18 + TypeScript + Vite + Tailwind + Leaflet
│   ├── components/       #   экраны: Hero, карта, «Разрыв», сводка, советы, чат-виджет
│   └── lib/              #   api.ts — клиент бэкенда; air.ts — презентационные хелперы
└── backend/              # бэкенд: Node 22 + TypeScript + Fastify + node:sqlite
    └── src/
        ├── routes/       #   HTTP-слой (валидация схемами, тонкие обёртки)
        ├── services/     #   композиция ответов (statusService, anomalyScan)
        ├── processing/   #   чистые функции: калибровка, AQI, IDW, fusion, аномалии
        ├── analytics/    #   фичи: прогноз, классификатор событий, оптимизатор сети…
        ├── external/     #   Open-Meteo, пробки (модель), стройки (демо-слой)
        ├── recommendations/  # rules-движок советов + профили + окно прогулки
        ├── mock/         #   генератор данных (пока нет железа)
        └── db/           #   схема, репозитории, seed
```

## Запуск

Нужен Node 22.5+ (используется встроенный `node:sqlite`). Два терминала:

```bash
# бэкенд — http://localhost:8080
cd backend
npm install
cp .env.example .env
npm run dev

# фронтенд — http://localhost:5173
npm install
npm run dev
```

При первом старте бэкенд сам создаёт SQLite-базу, заводит 6 демо-станций и засеивает 3 дня истории; мок-генератор пишет новые показания каждые 30 с. Ключи API не нужны.

## Как считается оценка воздуха

1. **Калибровка MQ** (`processing/calibration.ts`) — ADC → напряжение → сопротивление Rs (делитель с RL) → PPM по степенной аппроксимации кривых из даташитов Hanwei (`PPM = a·(Rs/R0)^b`). R0 хранится на устройство и пересчитывается командой калибровки.
2. **Компенсация T/RH** (`compensation.ts`) и **сглаживание** (медиана + EMA, `smoothing.ts`).
3. **Композитный индекс** (`aqi.ts`) — под-индекс на газ по EPA-стилю, итог = максимум.
4. **Fusion-покрытие** (`fusion.ts`) — ключевая идея максимального покрытия минимальной сетью: `PM2.5(точка) = фон Open-Meteo (есть везде) + Σ гауссовых поправок от станций (exp(−d²/2L²), L=3 км)`. Одна станция накрывает пятно ~6–8 км — полрайона; вдали от станций оценка честно сходится к городской модели. Покрытие — 100 % карты с переменной уверенностью, а не жёсткие слепые зоны.
5. **Слои города** — модельный индекс пробок по 9 магистралям и демо-слой строек добавляют явную надбавку к PM2.5 (расшифровывается в `status_reason`).
6. **Статус** (`status.ts`) — пороги ВОЗ по PM2.5 (15/35/75 µg/m³); MQ-композит может только ухудшить оценку, не улучшить.
7. **Аномалии** (`anomalies.ts`) — скользящий z-score, группировка в события; **классификатор** (`analytics/classifier.ts`) по отпечатку MQ2:MQ4:MQ8 различает пожар / утечку газа / трафик / выброс / инверсию (cosine similarity).
8. **Планирование сети** (`analytics/placement.ts`) — жадный set-cover по сетке плотности населения: текущие 6 станций покрывают ~67 % населения, +3 оптимальных → 90 %.

## Функции продукта

- **Статус «гулять / недолго / дома»** с прозрачностью: вклад каждого поста, уверенность, «измерение или интерполяция».
- **Персональная сводка** — погода, УФ, PM10-пыль, пыльца (6 видов), пробки, стройки; профили (младенец / ребёнок / астма / аллергия / пожилой / спортсмен / беременность) пересчитывают пороги на сервере.
- **Рекомендации** — что надеть, что взять (зонт, вода, маска FFP2, SPF), безопасная длительность, лучшее часовое окно прогулки.
- **Чат-ассистент** — rule-based, 11 интентов, отвечает живыми цифрами из API (без внешних LLM).
- **Аналитика**: «воздух в сигаретах» (Berkeley Earth), прогноз AQI на 6 ч (Holt + Open-Meteo), окна проветривания, доза вдоль маршрута (polyline), здоровье сенсоров (leave-one-out IDW).

Полный список из 24 эндпоинтов — в [backend/README.md](backend/README.md).

## Подключение реального железа

Прошивка ESP8266 шлёт `POST /api/ingest` каждые 30 с: заголовки `X-Device-Id` + `X-Signature` (HMAC-SHA256 тела), тело `{ ts, mq2_adc, mq4_adc, mq8_adc, temp_c?, humidity?, vcc_mv? }`. Секреты устройств — env `DEVICE_SECRETS=id1:secret1,...`. Мок отключается флагом `USE_MOCK=false` — весь остальной pipeline не меняется, потому что мок пишет в те же таблицы через тот же `processing/pipeline.ts`.

## Дисклеймер

Это индикатор, а не медицинский прибор. PM2.5 — модель Open-Meteo; MQ-сенсоры детектируют горючие газы и дым, а не пыль; пробки и стройки — модельные слои. Сайт сообщает об этом пользователю прямо в интерфейсе.
