# AUA — гиперлокальный мониторинг воздуха в Алматы

Сайт отвечает родителю за 5 секунд: **«Можно ли сейчас гулять с ребёнком в моём районе?»** — и честно показывает, откуда взялась оценка. Данные — собственная сеть станций на ESP8266 + открытые модели Open-Meteo (PM2.5, погода, пыльца).

## Железо

**Станция, которую мы собираем: ESP8266 + MQ-135.** MQ-135 реагирует на смесь продуктов горения — печное отопление частного сектора плюс выхлопы, — то есть ровно на то, из чего состоит зимний воздух Алматы. Он недорогой и работает круглосуточно без обслуживания, поэтому станции можно ставить десятками, а не единицами. Это и есть ответ на главный вопрос проекта: город нельзя покрыть дорогими официальными постами, но можно — дешёвыми.

Два дополнения поверх базовой сборки:

- **DHT22** — ставится на *часть* станций. Даёт температуру и влажность прямо в точке замера, поэтому поправка к кривой Rs берётся из собственных данных станции, а не из общегородского прогноза. Где его нет, замер помечается флагом `no_compensation` — это видно в API и на экране станции.
- **Светодиод** (зелёный / красный) — логика зашита в прошивку, поэтому станция отвечает без телефона, приложения и интернета. Текущий цвет отдаётся в API (`led`) и показан на карте и в списке станций.

В базе рядом живёт **демо-флот из шести станций MQ2/MQ4/MQ8** — его данные генерирует `mock/generator.ts`, чтобы приложение можно было смотреть целиком без железа. Каждая такая станция помечена `is_demo` и подписана «демо» в интерфейсе; на карте у неё пунктирный контур, у реальной — сплошной. Сгенерированные числа нигде не выдаются за измеренные.

Оба типа проходят один и тот же путь `processing/pipeline.ts`. Газовые колонки в БД **nullable**: устройство заполняет те каналы, которые физически несёт, а композитный индекс считается только по присутствующим. Ноль в отсутствующем канале был бы выдуманным измерением — и утёк бы прямо в итоговую оценку.

Это не лендинг, а приложение: пять экранов за таб-баром, который на телефоне
живёт снизу под большим пальцем, а с ширины `md` переезжает наверх.

| Экран | Маршрут | Что отвечает |
|---|---|---|
| Сейчас | `#/` | гулять или нет, что взять с собой, окно прогулки, откуда взялась оценка |
| Карта | `#/map` | наши станции, площадки под будущие, качество по районам, места для прогулки, пробки, слепые зоны, ваш адрес |
| Прогноз | `#/forecast` | 6 часов вперёд ML-моделью + её собственная точность |
| Станции | `#/stations` | парк постов; внутри — DHT22, газовые каналы, здоровье сенсора, аномалии |
| Дэшборд | `#/dashboard` | агрегаты города: динамика, суточный ритм, рейтинг районов, аптайм |

## Запуск

Нужен Node 22.5+ (используется встроенный `node:sqlite`). Два терминала:

```bash
# бэкенд — http://localhost:8080
cd backend
npm install
cp .env.example .env
npm run dev

# фронтенд — http://localhost:5173
npm install
npm run dev
```

При первом старте бэкенд сам создаёт SQLite-базу, заводит 6 демо-станций и засеивает 7 дней истории (столько же прошлого отдаёт Open-Meteo — так история сенсоров и погодные признаки покрывают одно окно); мок-генератор пишет новые показания каждые 30 с. Сразу после старта обучается прогнозная модель — это несколько секунд, до её готовности `/api/forecast/ml` отдаёт резервный прогноз и честно помечает его. Ключи API не нужны.

## Как считается оценка воздуха

1. **Калибровка MQ** (`processing/calibration.ts`) — ADC → напряжение → сопротивление Rs (делитель с RL) → PPM по степенной аппроксимации кривых из даташитов Hanwei (`PPM = a·(Rs/R0)^b`). R0 хранится на устройство и пересчитывается командой калибровки — только по тем каналам, которые устройство реально прислало. Для MQ-135 значение снимается как CO₂-эквивалент, и `cleanAirRatio` подобран так, чтобы чистый уличный воздух давал привычные ~400 ppm.
2. **Компенсация T/RH** (`compensation.ts`) и **сглаживание** (медиана + EMA, `smoothing.ts`).
3. **Композитный индекс** (`aqi.ts`) — под-индекс на газ по EPA-стилю, итог = максимум.
4. **Fusion-покрытие** (`fusion.ts`) — ключевая идея максимального покрытия минимальной сетью: `PM2.5(точка) = фон Open-Meteo (есть везде) + Σ гауссовых поправок от станций (exp(−d²/2L²), L=3 км)`. Одна станция накрывает пятно ~6–8 км — полрайона; вдали от станций оценка честно сходится к городской модели. Покрытие — 100 % карты с переменной уверенностью, а не жёсткие слепые зоны.
5. **Слои города** — модельный индекс пробок по 9 магистралям и демо-слой строек добавляют явную надбавку к PM2.5 (расшифровывается в `status_reason`).
6. **Статус** (`status.ts`) — пороги ВОЗ по PM2.5 (15/35/75 µg/m³); MQ-композит может только ухудшить оценку, не улучшить.
7. **Аномалии** (`anomalies.ts`) — скользящий z-score, группировка в события; **классификатор** (`analytics/classifier.ts`) по отпечатку MQ2:MQ4:MQ8 различает пожар / утечку газа / трафик / выброс / инверсию (cosine similarity).
8. **Планирование сети** (`analytics/placement.ts`) — жадный set-cover по сетке плотности населения: текущие 6 станций покрывают ~67 % населения, +3 оптимальных → 90 %.

## Прогноз на 6 часов — модель машинного обучения

`ml/` — градиентный бустинг решающих деревьев (CART на квадратичной ошибке), написанный здесь же, без внешних библиотек.

**Почему деревья, а не линия.** Драйверы алматинского воздуха нелинейны и работают в связке: ветер разгоняет чашу только выше порога, инверсия важна только в штиль и только после заката, час пик — только рядом с магистралью. Дерево глубины 3 выражает такое «И» напрямую; бустинг из сотни таких деревьев ловит структуру, которую одна трендовая линия Хольта увидеть не может.

**Отдельная модель на каждый час горизонта** (direct multi-step, h = 1…6) — так ошибка не накапливается, как при подстановке собственного прогноза себе на вход.

**37 признаков** трёх семейств (`ml/features.ts`):
- *локальная динамика* — лаги, скользящие среднее/σ и приросты нашего композита, газовые каналы, пара DHT22;
- *известное будущее* — почасовой прогноз Open-Meteo **на целевой час**: ветер, температура, давление, осадки, облачность, PM2.5, плюс индекс инверсии (штиль × ночь × холод × антициклон × ясно);
- *календарь* — час и день недели парами синус/косинус, чтобы 23:00 и 00:00 стояли рядом, и флаг часа пик.

Блок «известное будущее» — то, что отличает модель от экстраполяции тренда: она видит, что через три часа поднимется ветер, и знает из истории, насколько чаша при этом действительно продувается. Прошлое и будущее берутся **одним запросом** к Open-Meteo (`past_days=7&forecast_days=2`): если склеивать архивный и прогнозный API, на границе `t=now` возникнет разрыв, который дерево охотно выучит как настоящий сигнал.

**Валидация — по времени, а не случайная**: последние 25 % часов исключены из обучения целиком. Случайное перемешивание подмешало бы в обучение соседние часы целевого и дало бы красивую ошибку, которую живой прогноз повторить не смог бы.

Модель обучается на старте и переобучается раз в 30 минут; всё детерминировано (сид на подвыборке строк), так что два прогона на одной истории дают одинаковый прогноз. Карточка модели — метрики MAE/RMSE/R² по горизонтам, сравнение с базовой линией «ничего не изменится» и важности признаков — отдаётся в `/api/ml/model` и показана на экране прогноза: прогноз без ошибки внушает больше доверия, чем заслуживает.

## Сверка точности

Каждые 30 минут `services/referenceCollector.ts` складывает внешние показания PM2.5 в таблицу `reference_readings` рядом с нашими. `/api/accuracy` соединяет их с нашей часовой оценкой и считает MAE, **знаковое** смещение (сеть, которая систематически занижает, — это другая проблема, чем просто шумная), RMSE, корреляцию и долю часов в пределах ±5 и ±10 µg/m³. Архив нужен не только для проверки: чем он длиннее, тем точнее можно подогнать пересчёт нашего композита в привычный PM2.5.

Источник подключается через `external/reference.ts` и всегда подписан в ответе:

| Источник | `kind` | Когда |
|---|---|---|
| OpenAQ (эталонные станции, в т.ч. Казгидромет) | `station` | задан `OPENAQ_KEY` |
| Open-Meteo (та же модель, что даёт фон) | `model` | ключа нет |

Без ключа сверка идёт с моделью, и интерфейс говорит это прямым текстом: «проверка согласованности, а не точности». Согласие с моделью — гораздо более слабое утверждение, чем согласие с эталонным прибором, и подменять одно другим нельзя.

## Функции продукта

- **Статус «гулять / недолго / дома»** с прозрачностью: вклад каждого поста, уверенность, «измерение или интерполяция».
- **Персональная сводка** — погода, УФ, PM10-пыль, пыльца (6 видов), пробки, стройки; профили (младенец / ребёнок / астма / аллергия / пожилой / спортсмен / беременность) пересчитывают пороги на сервере.
- **Рекомендации** — что надеть, что взять (зонт, вода, маска FFP2, SPF), безопасная длительность, лучшее часовое окно прогулки.
- **Чат-ассистент** — rule-based, 11 интентов, отвечает живыми цифрами из API (без внешних LLM).
- **Данные станции** (`/api/stations/:id`) — DHT22 с производными (точка росы, абсолютная влажность, ощущаемая температура, вердикт по комфорту), газовые каналы и вклад каждого в композит, сырые значения АЦП, здоровье сенсора по четырём факторам, отпечаток текущего события, история за 6 ч / сутки / 3 дня / неделю.
- **Карта со всеми слоями** — действующие станции по PM2.5, площадки под будущие с радиусом покрытия и этапом, кружки статуса по районам, места для прогулки, пробки, слепые зоны и ваш собственный адрес; рядом — таблица «ваш район на фоне города».
- **Дэшборд** — KPI-плитки, динамика с полосой разброса, донат по долям часов, ритм недели, хитмап «станция × час суток», климат города, рейтинг районов и аптайм постов. Графики — свои SVG-компоненты, без чарт-библиотеки.
- **Аналитика**: «воздух в сигаретах» (Berkeley Earth), окна проветривания, доза вдоль маршрута (polyline), здоровье сенсоров (leave-one-out IDW).

Полный список эндпоинтов — в [backend/README.md](backend/README.md). Добавленные в этой версии:

| Эндпоинт | Назначение |
|---|---|
| `GET /api/forecast/ml` | прогноз на 6 ч ML-моделью, с интервалом ±1σ; падает в резерв (Хольт) и помечает это |
| `GET /api/ml/model` | карточка модели: гиперпараметры, метрики по горизонтам, важности признаков |
| `POST /api/ml/retrain` | принудительное переобучение (нужен `ADMIN_TOKEN`) |
| `GET /api/stations` | парк постов с последним замером, DHT22 и здоровьем — одним запросом |
| `GET /api/stations/:id` | всё об одной станции + история за окно |
| `GET /api/planned-stations` | площадки под будущие станции с этапами и приростом покрытия |
| `GET /api/dashboard` | агрегаты города под все графики дэшборда |
| `GET /api/dashboard/station-series` | детальная история одной станции |
| `GET /api/accuracy` | сверка нашей сети с внешним PM2.5: MAE, смещение, корреляция, доля попаданий |

## Подключение реального железа

Два канала приёма, оба заканчиваются в одном `processing/pipeline.ts`:

- **MQTT (MQ-135, работает сейчас).** Станция публикует `{ location, raw_adc, voltage, quality_percent, status }` в топик `MQ135_TOPIC`. `services/mq135Mqtt.ts` пишет пакет как есть в `mq135_air_readings` (нетронутый лог устройства) и одновременно проводит его через общий pipeline как обычное устройство — поэтому пост виден на карте, в списке станций и участвует в интерполяции. Координаты станции задаются через `MQ135_LAT` / `MQ135_LNG`: в payload их нет.
- **HTTP (`POST /api/ingest`).** Заголовки `X-Device-Id` + `X-Signature` (HMAC-SHA256 тела), тело `{ ts, mq2_adc, mq4_adc, mq8_adc, temp_c?, humidity?, vcc_mv? }`. Секреты устройств — env `DEVICE_SECRETS=id1:secret1,...`.

Мок отключается флагом `USE_MOCK=false`; остальной pipeline не меняется. **Новую станцию перед работой нужно откалибровать** на чистом воздухе (`POST /api/devices/:id/calibrate`) — до этого R0 стоит на разумном, но не измеренном значении по умолчанию.

## Дисклеймер

Это индикатор, а не медицинский прибор. PM2.5 — модель Open-Meteo; MQ-сенсоры детектируют горючие газы и дым, а не пыль; пробки и стройки — модельные слои. Сайт сообщает об этом пользователю прямо в интерфейсе.

## Деплой

- **Бэкенд** — Render: https://aua-backend.onrender.com. `CORS_ORIGIN` в переменных
  окружения сервиса должен перечислять фронтенд-домены через запятую (см.
  `backend/.env.example`); без прод-домена Vercel в списке браузер отклонит
  ответы по CORS. Free-инстанс Render засыпает после 15 минут простоя — первый
  запрос после паузы будет на несколько секунд дольше.
- **Фронтенд** — Vercel: https://aua-almaty.vercel.app. Требует переменную
  окружения `VITE_API_URL=https://aua-backend.onrender.com`
  (Project → Settings → Environment Variables, Production и Preview). Без неё
  собранный клиент обращается к `http://localhost:8080` и все пять экранов
  остаются пустыми — `src/lib/api.ts` откатывается на этот адрес, только если
  `VITE_API_URL` не задан.
